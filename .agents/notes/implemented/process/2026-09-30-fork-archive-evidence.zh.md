# Agent Note: 不可变的 fork 归档证据

Status: implemented

[English](2026-09-30-fork-archive-evidence.md) | 中文

## 问题

Fork 集成在上传前记录了 14 个分支归档候选和 33 个远端引用。发行 tag 无法替代这些实际观察到的精确提交标识：快照记录了尚未创建的拟议 tag、空的分支删除列表，以及采集时的认证限制。[维护中的引用策略](2026-09-12-maintained-repository-references.zh.md)拒绝普通维护文件中的这些标识。

## 决策

在[带日期的历史快照](../../../../docs/history/2026-09-30-fork-archive-manifest.json)中保留原始 JSON 字节。[引用检查](../../../../scripts/verify-repository-references.ts)要求这一精确路径及其固定 SHA-256 封存摘要匹配，才允许其中的历史提交标识。该例外不改变组织 URL 检查或其他文件的提交引用策略，也不授予删除分支或创建 tag 的权限。

封存摘要覆盖所有字段、记录和字节，包括历史状态。证据缺失或改动均会失败，不依赖可用的 Git 历史。不得更新此快照或刷新封存摘要来描述当前状态。后续采集需要单独审查策略变更，明确其精确路径、原始内容封存摘要及完整性测试；禁止排除整个目录。

## 考虑过的替代方案

**使用冻结的 Agent Note 目录。** 其归档只接受已有的已实施双语三件套，不接受原始 JSON 证据。快照与这些产物及其不可变封存摘要分开存放。

**排除整个历史目录。** 这会允许无关文件保留禁止的引用。只有精确匹配封存摘要的快照允许提交标识。

**仅检查记录数量。** 替换标识和修改采集状态后，数量仍可能不变。固定内容摘要可检测任何改动，同时保留完整的原始证据。

## 影响

快照仍是历史观察，不是当前远端状态，也不是清理分支的指令。测试检查 14 个候选和 33 个引用，拒绝删除和篡改，并验证同目录文件及复制的证据仍受维护中的引用策略约束。通用引用策略保持活跃，仍具有独立价值。
