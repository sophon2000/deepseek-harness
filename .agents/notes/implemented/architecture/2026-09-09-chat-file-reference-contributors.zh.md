# Agent Note: 聊天文件引用提供方

Status: implemented

[English](2026-09-09-chat-file-reference-contributors.md) | 中文

## 问题

Deliverables 原先独占收尾正文的文件解析器。领域插件可以在工具卡中展示 已核对的资源，却无法在不替换原生解析器的情况下，让回复中的资源名打开同一预览。

## 决策

Chat 拥有 `chatFileMentions`。插件通过 effect 注册具有唯一 ID 的提供方。 每个提供方读取收尾轮次的投影事实，返回精确名称、可选别名、无障碍标签及预览回调。 Chat 优先匹配精确名称，其次匹配别名；任何歧义匹配都不生成链接。

注册表暴露版本快照。注册与 dispose（资源释放）更新该快照，触发收尾正文 重新渲染，并使提供方名单改变前捕获的回调失效。打开引用时，插件仍负责核对 来源会话、资源身份与读取权限。

Deliverables 提供同轮成功变更及声明交付的路径。正文回调使用已有应用内文件预览。 原生应用和文件管理器操作仍是交付文件卡上的显式选择。 Chat 不根据文件名推断资源，也不自行签发播放凭证。

## 考虑过的替代方案

**每个领域插件替换原生解析器**无法组合，并使插件顺序决定哪些资源仍可点击。

**扫描全部正文并查找文件名**会猜测身份、在渲染时引入读取，且丢失产出轮次的资源版本。

**每次读取都要求 present**会混淆检查既有资源与声明交付文件；只读领域引用不需要它。

## 影响

领域资源可复用原生行内代码链接样式和既有预览，无需新增播放器或模型工具。 旧回复可通过回放工具事实恢复引用；单独的文件名不构成权限。 两个提供方指向同一资源时，除非提供无歧义的写法，否则仍视为歧义。这是有意保守处理。

## 测试

注册表测试覆盖精确与别名匹配、冲突、重复提供方 ID、版本通知和陈旧回调。 Deliverables 测试验证正文打开应用内预览，显式原生操作仍保留凭证检查。
