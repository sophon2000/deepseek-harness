# Agent Note: 解析已安装的 Typert Remote 类型

Status: implemented

[English](2026-08-31-installed-typert-remote-types.md) | 中文

## 问题

树外插件使用已安装的 DSH 声明，而不是工作区源码。将 Remote 协议身份和具名查找传输类型限制为工作区注册项，会导致这些插件无法生成带作用域的 Remote 声明，即使依赖包已经公开了所需类型。

## 决策

分析器识别已安装的 `@deepseek-ai/dsh-typert-protocol` 包拥有的协议声明。包身份要求解析后的 node_modules 路径与包 manifest（元数据清单）名称一致。其他名称的包不会因声明同名而获得协议语义。

已安装包的具名传输类型使用在所属包内解析的具体公开非根导出。导出模块必须已包含在编译程序中，其导出符号必须解析为原始声明。生成的类型导入在符合条件的导出中作确定性选择。仅从根入口导出的具名传输类型会导致生成失败；本次不增加通配符导出发现。

## 考虑过的替代方案

**要求提供 DSH 工作区源码。** 未采用，因为独立安装的插件必须能够在没有 DSH 源码检出的情况下生成产物。

**使用包根入口或私有声明路径。** 未采用，因为生成的客户端将依赖面向宿主的入口或未公开的文件布局，而不是包显式提供的类型导出。

## 影响

已安装包的查找和上下文传输类型保留公开声明身份，不改变运行时授权或编解码器的开放语义。包发布方必须公开可达的具体类型子路径。生成器测试覆盖已安装包的查找／上下文元数据、规范生成导入、根入口专属类型的拒绝，以及其他名称的协议包；这项修改不代表发布了新的包版本或取得了运行时兼容性资格。
