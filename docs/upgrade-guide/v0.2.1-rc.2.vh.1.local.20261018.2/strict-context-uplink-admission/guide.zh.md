# 重建严格上下文与流入站校验

[English](guide.md) | 中文

## 变更

生成的 LIB 描述符现在为作用域上下文身份与客户端到 Host 的上行流消息提供可选的 `strictCodec`。Host 入站校验在解析作用域目标或投递上行消息之前优先使用此编解码器。此前这些路径使用普通编解码器，可能接受对象并剥离未声明字段。发送额外根字段或嵌套字段的调用方现在会收到校验失败。

普通编解码器与结果解码保持既有行为。没有 `strictCodec` 的 SRC 或手动注册描述符仍回退到普通编解码器。只升级 Host 不会让旧生成描述符变严格：还必须重新生成对应元数据。参见 [Typert 契约](../../../subsystems/typert.zh.md)。

## 迁移

1. 获取完整配套候选发行包并核对清单与完整性。所有 DSH 包版本固定值与配置档运行时必须使用同一候选版本；不要用重建字节覆盖已有版本。使用 Reader 或 Video 集成时，还须安装配套集成包。
2. 使用配套的 `@deepseek-ai/dsh-typert-generator` 重新生成 Host 与远程客户端描述符，然后重建相关包及嵌入其生成元数据的 bundle。范围包括作用域上下文方法和双向流；只替换 `@deepseek-ai/dsh-api-gateway` 不够。
3. 根据声明的身份或上行消息类型，从调用方请求构造中删除未声明字段。保留合法的索引对象键与交叉类型字段。不要添加校验前剥离步骤，也不要放宽模式来让无效消息成功。
4. 检查生成的上下文调用与上行描述符是否含 `strictCodec`。通过真实打包 Host 测试合法消息、未知根字段与嵌套字段、已知字段类型错误以及合法索引交叉类型。无效上下文身份不得解析目标；无效上行消息不得到达接收流。
5. 分别复验普通结果解码与 SRC/手动描述符回退。完成严格消费者类型检查、已安装包身份检查和应用配置档测试后，再替换此前可用的安装。
